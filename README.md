# 断电以后

一款原创中文纯文字生存游戏。玩家提前七天得知城市将因不明传染病封锁，需要在灾前用有限金钱和每日时间准备避难所；停电后按游戏内时钟管理状态、处理事件、使用家具、探索地点，并设法活到撤离或找出封锁背后的真相。每天会获得一个明确愿望和一组额外委托，用当天积累的点数挑选即时奖励。

游戏完全在浏览器本地运行，不需要后端或网络连接。每次完整行动后都会写入 `localStorage` 自动存档。

## 本地启动

要求 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev -- --host localhost
```

浏览器访问：<http://localhost:3000>

运行游戏时请保持执行上述命令的终端开启；关闭终端或结束开发服务后，网页会暂时无法访问，但浏览器里的存档不会因此消失。重新执行命令即可恢复访问。请始终使用同一个地址 `http://localhost:3000`，不要在 `localhost`、`127.0.0.1` 或其他端口之间切换——浏览器会把它们视为不同站点，并为它们保存互不相通的本地进度。

生产构建与本地检查：

```bash
npm run typecheck
npm test
npm run lint
npm run build
```

## GitHub Pages 发布

仓库包含 [`.github/workflows/pages.yml`](.github/workflows/pages.yml)。推送到 `main` 后，GitHub Actions 会先运行类型检查、测试和代码检查，再生成纯静态版本并发布到：

```text
https://<GitHub 用户名>.github.io/<仓库名>/
```

首次发布需在仓库的 `Settings → Pages → Build and deployment` 中选择 `GitHub Actions`。线上站点与 `http://localhost:3000` 属于不同网址，因此两边的浏览器 `localStorage` 存档不会自动互通。

## 游戏规则

### 灾前七天

- 开局前可选 `简易`、`标准`、`艰难`。简易默认推荐：初始现金和物资更多、白天更长、探索风险更低、每日奖励更丰厚，并在第 10 夜开放撤离；标准与艰难需要坚持到第 14 夜。
- 开局还可选择不借贷、短期周转或高息应急款。借款会立即增加采购现金，但账面偿还额高于到手金额；封锁期可花 30 分钟偿还最低额或一次结清。到期未清会逐夜增加费用、降低精神，连续催收还会损伤避难所，并为所有危险判定增加可见风险。
- 顶部日期摘要和右下角固定状态区会持续显示剩余现金；工作、采购或设施改造后会随自动存档立即更新。
- 每次涉及现金或时间的行动会在页面中央显示醒目的结算浮层，例如 `-¥70`、`08:30 → 11:30 · +3小时`；状态区的现金和时钟也会同步闪动，历史反馈条保留本次行动耗时。
- 一天从 08:00 开始。每个行动显示准确耗时，时钟到达当前难度的日终会自动跨日；也可以提前就寝。行动不再受固定行动点限制。
- 工作耗时 4 小时并获得金钱，每天限一次；收入按难度为简易 ¥170、标准 ¥140、艰难 ¥115。商店采用可复现的当日库存：第一天货架最完整，第二天起因恐慌、停运而逐日减少，后期会标出限量、最后一件和缺货，售罄后当天不会补货。
- 前六天前往商店耗时 1 小时 30 分。每次出门都有独立的随身包上限（简易 18 kg、标准 12 kg、艰难 9 kg），购买还会同时检查现金和避难所总储物空间；同一家店每天只允许进场一次，不能靠反复出入重置限购。
- 第七天正常零售停止。当天仅可进行一次冒险采购，会消耗 2 小时 30 分并触发高风险判定：可能受伤空手返回，也可能在无人收银的残余货架免费带回少量随机物资；整个结果由种子复现。
- 可以加固门窗、改造储水、分三级建设备用供电、调查情报、联系四名邻居或休息。完成一级供电后还能做一次全屋停电演练，提前找出电器冲突并回收可用电芯。
- 食物、饮水、药品、工具、能源、防护、材料和特殊物品都有分类、价格、重量、准确状态点数与用途。背包中的每种物资都会标明保存期限：普通物资显示“长期保存”，易腐物按入库批次显示“剩余 N 天”或“今天到期（今日可用）”。简易难度商店会显示“必备 / 推荐”及建议目标数量。

### 每日愿望与即时奖励

- 每天开始会根据阶段、剩余时间与可用资源直接指定一项当天能够完成的愿望，不再要求玩家挑选愿望或设置完成时限。
- 愿望第一次达成时会记录准确时刻。简易难度日终获得 2 点“愿望点”，标准与艰难获得 1 点；即时奖励的成本与数量也按难度标定，简易可以持续获得丰厚补给，标准与艰难的物资奖励只能补贴整局消耗，不能单独养活玩家。
- 每天还会按阶段发布一至两项额外委托，例如采购、修缮、联络或完成探索。每项只结算一次，完成时立即获得 1 点并写入一条日志；日结只汇总，不会再次加点。
- 愿望未达成时不发愿望奖励，也不扣状态、资源或已有点数；委托已经获得的点数仍会保留。愿望完成后，右上悬浮提示会自动弱化，避免遮挡主要内容。
- 玩家可以领取当日奖励，也可以选择“暂不领取”把全部点数留到后续日期；愿望点不会带入下一轮。它与结局后用于购买永久能力的“残留记忆”是两套独立资源。

### 封锁以后

- 每天 07:00 开始，行动耗时从 20 分钟到数小时不等；封锁后每经过 2 小时会按难度追加少量饱腹和水分消耗。休息仍能恢复体力和精神，但时间本身有代价，低体力也不能继续透支执行修缮、加固或外出。
- 每晚结算饱腹、水分、体力、精神、天气、供电、避难所和伤病，并按难度自然降低精神；难度还会改变消耗、风险、白昼长度和撤离天数。艰难模式从第 8 夜进入三段后期压力：夜间食水消耗逐段提高、睡眠恢复下降，右侧“今日”分页会提前列出当天采用的压力数值。
- 饱腹或水分降到 40 以下会在中央持续显示橙色预警，20 以下升级为红色危险提示；界面同时显示基础夜耗后的预计值与现有库存能否补足。低于 35 会直接提高所有危险判定，低食水在夜间还会损失精神并抵消睡眠体力恢复，严重饥渴会继续损伤健康。“危机耐受”永久能力会真实削弱低精神造成的风险与心理惩罚。
- 夜间自动补充的目标线为 60：系统先考虑临期批次，再比较厌倦增量、料理/交易保留价值和当前缺口，可连续使用多份食水；瓶装饮品不足时会继续逐单位取用净水箱。简易默认开启，标准与艰难默认关闭，但三种难度都可在开局或当前局设置中自由切换。
- 公寓自带双门冰箱、燃气炉、微波炉和电火锅，不占背包重量。玩家可随时把夜间负载设为“均衡供电”“保鲜优先”“照明优先”或“彻底节电”：保鲜能延长易腐批次寿命，照明与充电改善精神和休息，节电则保存电量但承受黑暗。夜间电力统一按“已知天气损耗 → 陷阱 → 尸潮警戒 → 舒适回路”预留，右下角、策略卡、围攻预览和真实结算使用同一个预算函数；暴雨不会再抢走界面已承诺给陷阱的电。电池可直接并入回路补 3 点电力；燃料罐含 6 点燃料，但必须先在灾前五金店购买 8.6 kg 的静音燃油发电机并完成一级供电改造，之后每运行 30 分钟以 3 燃料换 5 电力。发电机本体不会被消耗。
- 6 个地点全部采用深入文字地图，共 33 个相连区域：超市侧重食材与仓储，诊所侧重药品和转运记录，五金行侧重工具与变电站钥匙，地铁侧重维修通道和封锁报码，变电站侧重供电与样本，公交总站侧重撤离名单和燃料。中央会持续显示按入口最短路线分层的“区域路线图”，标出当前位置、相邻可直达区、已发现状态、目标进度和入口参考路线；点击相邻节点可直接移动，非相邻节点会说明需要逐段前往。进入、移动、处理目标和返程分别计时，途中刷新页面也可原位继续；从任意区域选择撤离时，系统会沿参考路线自动折返，室内返路已经计入固定回程窗口。艰难难度首次探索的普通战利品按种子保留标准模式约 65%，但钥匙、证据和其他剧情物品完整保留。
- 幸存者交易不再固定为两项：陈檬、林舟、潘岳和邱岚各有三项符合其立场的报价。系统按本轮种子与封锁天数，从已通过广播联络的人物中每日抽取最多三项；同一天刷新网页不会重抽，跨日才更换。简易可逐笔交换，标准与艰难每天最多成交一笔；成交严格检查付出物、所得重量和剩余时间。
- 广播建立人物联络后，不必再等待对方触发事件：可从“主动联络与幸存者交易”中指定人物，并选择职业咨询或投入对方重视的物资。每人仍然每天最多一次，同时设全局额度：简易 4 次、标准 3 次、艰难 2 次。艰难通讯优先消耗 2 点电力，其余难度为 1 点；其次消耗电池，没有能源时则用时间和体力手摇发电。咨询提供信息与关系，不再凭空治伤或修复房屋。
- 每名人物都公开职业能力与结盟门槛。信任达到 24 后可主动邀请结盟：陈檬让困难围攻额外吸收 2 点，林舟让外伤和感染每夜各少损失 1 点健康，邱岚降低所有危险判定 3 点，潘岳仅让消耗材料的施工额外恢复 3 点完整度。结盟状态与职业效果会随本轮存档保存。
- 各地点的药柜、货架、设备间、电缆沟、控制层和调度档案等目标都提供至少两种处理方式。开锁组、撬棍、工具箱、多用钳、手斧、绳索及剧情线索会形成不同噪声、体力、风险、状态效果与战利品结果；情报及开锁、工具使用、观察搜寻三项现场技能还能解锁更完整的路线。每 3 XP 提升 1 级。普通搜刮点同日不能重复领取、下一封锁日刷新；标准与艰难模式反复进入同一地点时补货会逐次枯竭。故事钥匙、证据与已处理的剧情设施永久记录。
- 危险标签直接显示当前受险概率。执行时生成 `1—100` 的种子随机值：随机值大于风险线则安全；不高于风险线但高于其一半会产生轻微后果；不高于风险线一半会产生严重后果。日志会展开“基础风险 + 难度 + 低状态 + 债务 - 装备 - 地图 - 情报”的完整算式，因此结果既有概率也能追溯原因。
- 第 6 天出现尸潮预警，第 8 天经过主要尸潮。困难模式会在第 3、5 夜遭遇前期试探，并从第 8 夜开始连续七夜受到每日升级的大规模围攻，最终冲击从 20 增至 34。即使冲击被完全挡住，守夜仍会损耗体力和精神；有电的楼道警戒线每夜额外消耗 1 点电并减少疲劳。当天界面会提前显示“冲击 − 加固吸收 = 预计损伤”及加固磨损，不会暗扣结构值。
- 艰难模式可在“供电与夜间负载”安装三级电力陷阱，并随时接通或断开。尸潮结算顺序为“冲击 − 电力陷阱主动攻击 − 加固与盟友吸收 = 结构损伤”；陷阱每波真实耗电，电力不足则不触发，因此发电、储能和防御需要一起规划。
- 困难模式第 9 天以后会在非关键剧情日优先安排库存压力事件，而且只会选择玩家当前确实持有对应物资的类别。水、耐储食物、绷带与消毒液、电池与燃料罐、木板与钢板都有不同去向；玩家可投入物资换取协防、情报或信任，也始终保留拒绝选项，不会因库存不足卡死。
- 木板耗时 2 小时，提供完整度 +20、加固 +1；薄钢板需要工具箱并耗时 2 小时 30 分，提供完整度 +32、加固 +2。工具箱与胶带可完成正式修缮；没有材料时每天只能搭一次临时支撑，艰难仅恢复 2 点，不能与休息组成无限维修循环。每级加固在每一波中吸收 2 点冲击，第 8 夜后的大型波次会磨损 1—2 级加固，因此后期仍需搜集材料、修缮并重新封固。
- 简易难度第 8 天、标准与艰难第 12 天会稳定出现一次外联抉择。承诺发送后，还需收集至少三份证据、取得两名可信联系人的信任、解码广播，并保留短波收音机、铜线卷和至少 6 点备用电力，才可尝试建立证据路线；发送必定消耗铜线卷 1 与电力 6，事故造成的额外耗电另算，窗口每轮只能尝试一次。这里的“可信联系人”门槛低于正式结盟门槛，界面会分别标示，不再混称为盟友。
- 活过最后一夜后，玩家必须亲自选择普通撤离、在证据发送成功时选择维修通道，或主动放弃车位留守街区。满足隐藏条件不会自动覆盖普通结局；普通、隐藏与死亡结局会根据盟友、联络情况、债务、证据来源、天气、尸潮、路线和具体死因生成不同尾声。
- 精神降到 20 以下且连续两天没有真实交流时，会累计“连续孤立”夜数。收听到活人、主动联络、交易，以及确实包含当面或远程交流的事件选项都能刷新联络日；独自守夜、旧广播记录和不回应他人的选项不能伪造联络。第一夜开始预警，连续三夜未能逆转会进入“最后一次广播没有发出”的孤立死亡结局。其他死亡会区分饥饿、脱水、感染、外伤、失温、闷热、过劳、尸潮破门、风雨坍塌与一般避难所失守。
- 所有强制事件至少保留一个不依赖特定物品的选项；任何行动阶段都可以提前结束当天，因此不会因缺少剧情物品永久卡死。

### 轮回与操作

- 死亡、普通幸存和隐藏结局都会留下永久的“残留记忆”。它只在一轮结束后发放，可解锁 `仓管直觉`、`旧城地图`、`危机耐受` 三项永久能力；每日“愿望点”则在当天结算并立即使用。
- 底部选项对应数字键 `1`—`9`；也可使用鼠标、触控、Tab、Enter 和 Space。
- 设置中可以关闭数字键、减少动画、提高对比度、调整字号或关闭新手提示。
- 标题页可输入种子。下一轮会默认生成新种子以减少重复；手动输入相同种子并做出相同选择，仍会复现相同事件、天气、战利品与危险判定。
- 核心状态固定显示在桌面右下角；手机宽度下会压缩为两行状态网格并保持在行动区上方。
- 右下角同时显示 `饮食厌倦`（越低越好）。模型同时记录全局厌倦、每种食物的长期熟悉度、永久吃过的菜单、同类口感疲劳与最近十餐；同一种食物连续出现、A/B 两种食物交替、长期依赖少数食物或换名字反复吃同类主食都会累积负担。每个物品的使用预览与真实结算调用同一个公式，因此不会出现提示说“会降低”但实际增加的情况。
- 真正首次出现的新鲜食物或热料理只能有限缓解全局厌倦，不能清除玩家对其他食物的长期熟悉度；失败料理会更快增加厌倦。简易、标准、艰难的正向累积倍率依次提高，三种难度都不能靠两种食物交替重置。单品熟悉度每夜分别衰减 4/3/2 点，全局厌倦每夜衰减 2/1/1 点；厌倦达到 40、60、75、90 附近时会逐步加重精神代价。手动进食与夜间自动配给完全共用这套规则。
- 封锁后每个夜晚都会自然降低精神：简易 −1、标准 −2，艰难从 −4 逐步升至后期 −7。状态区会提前显示今夜损耗。玩家可在家具与制作菜单进入“娱乐与放松”：写日记、阅读、摆牌或听音乐都会消耗少量体力并恢复精神；小说和扑克牌需要灾前购买，音乐还会消耗电力或电池。同一娱乐每天只能结算一次，所有活动都会推进时钟。
- 储水装置把“可饮用净水”和“待净化原水”分开保存。净水可按需取用 1—4 单位，每单位都能转化为水分；即使只剩 1—3 单位也可以手动饮用或被夜间自动配给使用。暴雨、酸雨和渗漏收集到的原水不能直接喝，必须用净水片和滤布处理后才进入瓶装水库存。
- 左侧物资抽屉新增“档案”分页：已发现线索显示完整内容，未发现线索只显示来源提示；料理成功后还会在同页永久记录本轮配方。右侧简报拆分为“今日 / 技能 / 人物”，减少单栏堆叠。
- 行动卡片和背包中可能省略的名称、条件与说明均带完整悬浮信息；键盘用户可聚焦行动按钮并由辅助技术读取完整标签。

## 项目结构

```text
app/                  页面入口、全局样式和元数据
components/           标题页、游戏主界面、状态栏、背包、行动区与弹窗
game/data/            难度、压力、借贷、愿望与委托、线索、陷阱、家具、物品、地点、NPC、天气和事件配置
game/engine/          时钟、债务、每日结算、料理、供电陷阱、商店、交易、围攻、探索、随机数、背包、结局和存档逻辑
game/types.ts         游戏内容与引擎的共享类型
tests/                状态、背包、存档、结局、内容下限与终止性测试
public/og.png         社交分享预览图
```

引擎与内容配置没有直接依赖 React；界面只调用引擎公开的事务函数，并在成功结算后统一保存。

## 扩展事件

1. 在 [`game/data/events.ts`](game/data/events.ts) 的 `EVENTS` 数组新增一个唯一 `id` 的事件。
2. 指定适用阶段 `phase`、可选日期、天气、前置旗标和互斥旗标。通过玩家自己的收音机才能发生的场景必须声明 `requiresRadio: true`；跨天事件使用相同 `chain.id` 与递增的 `chain.step`，后续节点用前一选择写入的旗标控制。
3. 每个选项填写玩家可预知的 `hint`、原创 `result` 和具体 `effects`；只有实际包含活人交流的分支才添加 `countsAsContact: true`，若整个场景无论选择都确认了活人信号则放在事件级。强制事件至少保留一个不要求物品的选项。
4. 物品引用必须来自 [`game/data/items.ts`](game/data/items.ts)。新增物品时同时填写价格、重量、类别、用途、商店和可选保质期。
5. 可直接使用的物品在 `effects` 中填写状态点数；如需在简易难度给出采购指导，添加 `easyPlan: { tier, target }`。界面会自动生成分类、点数和推荐标签。
6. 不要使用 `Math.random()`。所有事件抽取、战利品与危险判定必须经 [`game/engine/rng.ts`](game/engine/rng.ts) 的种子随机流。
7. 运行 `npm test`；内容测试会检查最低数量、事件链数量、强制软锁、时间结算、难度、家具和存档迁移。

### 扩展深度探索地点

1. 在 [`game/data/deep-additional-locations.ts`](game/data/deep-additional-locations.ts) 增加地点、区域、双向连接和目标，再把地点加入 `ADDITIONAL_DEEP_LOCATIONS`。超市示例保留在 [`game/data/deep-exploration.ts`](game/data/deep-exploration.ts)，叙事配置与处理逻辑分离。
2. 每个目标可以配置多种方法，各自声明耗时、体力、所需物品、最低技能、最低情报、前置旗标、危险值、战利品、经验、统一状态效果和剧情旗标。工具默认只作为条件，不会凭空消耗；需要耗材时使用 `consumes`。
3. 每个区域都应能沿连接返回，目标也必须允许玩家“先不处理”。路线图由 [`game/engine/deep-map.ts`](game/engine/deep-map.ts) 自动执行入口 BFS，不要为只有拓扑关系的数据虚构真实方位；只有当叙事必须严格表达楼层、东南西北时，才应另加人工校对的坐标配置。
4. 引擎会为返程时间做硬预留；撤离会沿当前节点到入口的参考最短路线自动折返，因此不要绕过 [`game/engine/deep-exploration.ts`](game/engine/deep-exploration.ts) 直接修改时钟或背包。
5. 所有 `LOCATIONS` 会自动路由到同 ID 的深入地图。新增配置后运行测试；引用校验会检查区域可达性、双向返程、解法数量及未知需求、消耗、效果与战利品物品，路线图测试还会检查全部节点可达及最短返程路径。

事件后果使用统一的 `EventEffect`：可改变核心状态、避难所、物品、金钱、情报、人物信任、伤病或剧情旗标。所有变化都会进入即时反馈和历史日志，不应直接在界面层修改资源。

每日愿望与奖励配置在 [`game/data/daily.ts`](game/data/daily.ts)，每日委托配置在 [`game/data/commissions.ts`](game/data/commissions.ts)。新增目标时指定阶段和匹配的行动 ID，并由 [`game/engine/wish-plan.ts`](game/engine/wish-plan.ts) 分配、[`game/engine/daily.ts`](game/engine/daily.ts) 单次结算。线索档案在 [`game/data/clues.ts`](game/data/clues.ts)，电力陷阱在 [`game/data/power-traps.ts`](game/data/power-traps.ts)。周期性食水与后期恢复统一配置在 [`game/data/pressure.ts`](game/data/pressure.ts)，不要在界面和日结引擎中各写一套数字。

## 存档说明

- 本轮存档键：`after-power-game-v4`。保存当前难度、天数与时钟、随机种子和随机流、所有状态（含全局饮食厌倦、单品/同类熟悉度、永久吃过的菜单、近期十餐和最近真实联络日）、金钱、债务、净水与原水、电力陷阱、家具、分批背包与到期日、商店库存、天气、伤病、NPC、剧情旗标、现场技能、探索进度、当前事件、愿望与委托、愿望点、已解锁料理配方、待处理日结、结局和历史日志。
- 轮回记忆键：`after-power-meta-v1`。保存记忆点、完成轮数、永久能力、已见结局和已领取奖励的轮次。
- 阅读设置键：`after-power-settings-v1`。保存快捷键、减少动画、高对比度、字号和新手提示设置。

这些内容会以 JSON 写入当前浏览器的 `localStorage`：新开一轮、生成每日愿望、每次成功行动、购买物品、处理事件、跨日、领取或确认奖励、切换设置或购买永久能力后都会立即保存。刷新页面后回到标题页，点击“继续游戏”即可恢复；即使刷新发生在“待处理日结”界面，也不会重复发点或跳过结算。

存档不是项目目录中的文件，而是仅存在于当前浏览器、当前用户配置和当前网址下，没有后端或云同步。隐私窗口、其他浏览器、不同端口或清除浏览器站点数据都无法读取这份进度；清除站点数据还会永久删除本地存档。

“重新开始”只覆盖本轮进度，不清除记忆、永久能力和已见结局。

旧版 `after-power-game-v3` 会保留当前局并补入单品/同类食物熟悉度、已尝试菜单、最近联络日与原水字段。由于 v3 没有保存当前剩水的来源，升级时会把现存水保持为可饮用净水，避免历史雨水日志把后来取得的净水误判为原水；升级后新收集的雨水仍会严格进入原水。`after-power-game-v2` 会补入每日系统；更早的 `after-power-game-v1` 还会自动补入标准难度、当天起始时刻和四件满状态自带家具。缺少供电策略的旧存档会默认采用“均衡供电”。首次继续保存后统一写入 v4；加载时已过期的旧批次不会重新变成可用物资。

- 在老潘五金行找到的“变电站铜钥匙”会解锁北湖变电站控制层支线；钥匙不会消耗，并能避开高风险备用入口。没有钥匙时，也可通过相关事件获得“备用入口路线”后潜入。控制层只能搜查一次，可获得样本证据并补充避难所电力；露天开关场的站用蓄电柜同样只能安全拆取一次，不能逐日刷电。
- 四名幸存者不会在开局直接公开。灾后每完成一次有效广播收听，就会按顺序建立一名人物联络；未联络人物不会进入具名事件或交易。灾前给邻居留言可在首次联络时转化为初始信任。
- 广播不是只检查背包里有没有收音机：主动收听需要 2 点备用电力、电池组 1 或手摇体力 12；被动广播事件也会结算 1 点电力、电池组 1 或手摇体力 8。没有任何供能来源时广播事件不会进入候选，接收方式会显示在事件卡和日志里。
- “夜间自动补充”会在饱腹或水分低于 60 时使用合适的食物、饮水或净水箱，并尝试连续补到目标线。简易难度默认开启，标准与艰难默认关闭；三档均可在开局页或游戏设置中随时切换，选择会随本轮存档保存。原水永远不会被自动饮用。
- 标准与艰难难度的工资、愿望收益、联络次数和交易次数更紧。标准模式重复探索同一地点时，普通补货会从 75% 逐步降到 25%；艰难细化地图还会叠加封锁日稀缺系数，从首次约 65% 继续降到后期约 20%，并随重复进入进一步枯竭，单件货格可能为空。故事钥匙与证据不参与削减，也不会随每日刷新重复生成。
- 食材与料理系统包含多种饮品、主食、蛋白、蔬菜和调味品。选择燃气炉、微波炉或电火锅后，可以勾选任意现有食材并预览是否匹配已知做法；成功料理会生成有保质期的成品，并把配方记入“档案”。累计每 3 次尝试提升 1 级料理技能，最高 5 级并提高后续成功率。
- 烹饪不要求先凑齐完整配方：任何可烹饪物都能尝试，所选食材会被严格消耗，不会误用未选择的库存。完整组合采用正常成功率；不匹配时会按全部所选食材进行即兴烹饪，以较低成功率生成临时热杂烩或失败料理，时间和能源仍会真实消耗。
